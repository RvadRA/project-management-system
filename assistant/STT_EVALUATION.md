# Оценка локального распознавания речи

## Текущие настройки

Backend читает `STT_MODEL`, `STT_BEAM_SIZE` и `STT_CPU_THREADS` при старте.
Модель по умолчанию — мультиязычная `base`; `beam_size=1` и два CPU-потока
сохраняют лёгкий режим. Изменение beam size не следует считать улучшением,
пока оно не проверено на одном и том же аудио: большее значение может
увеличить время и потребление ресурсов.

Выбор модели и decoding-параметры можно переопределить переменными окружения
в PowerShell перед запуском backend; `.env` менять не нужно:

```powershell
$env:STT_MODEL = "base"       # или "small"
$env:STT_BEAM_SIZE = "1"      # лёгкое значение по умолчанию
$env:STT_CPU_THREADS = "2"
.\venv\Scripts\python.exe manage.py runserver
```

Для изменения настроек остановите backend и запустите его заново с нужными
значениями. Django читает конфигурацию при запуске процесса.

Чтобы сравнить `base` и `small` на одной и той же речи, подготовьте WAV PCM
16 кГц, моно, 16 бит длиной не более 60 секунд. Команда сначала полностью
распознаёт файл `base`, освобождает экземпляр модели, затем загружает и
распознаёт `small`. Одновременно обе модели не загружаются. Первый запуск
каждой модели может скачать её в локальный каталог кэша.

Из корня проекта запустите:

```powershell
.\venv\Scripts\python.exe manage.py compare_speech_models "C:\путь\к\тесту.wav" --language ru
```

Команда печатает модель, время обработки и полученный текст для каждой
модели. Она не подключается к БД, не сохраняет транскрипт и не обращается
к Ollama или внешнему API распознавания.

Для сравнения другого языка укажите `--language en`, `--language uz` или
`--language auto`. Используйте одни и те же файлы, язык, настройки потоков и
beam size для сравниваемых запусков. Чтобы отдельно проверить другое значение
beam size, установите его в переменной окружения **до запуска команды**:

```powershell
$env:STT_BEAM_SIZE = "1"
.\venv\Scripts\python.exe manage.py compare_speech_models "C:\путь\к\тесту.wav" --language ru
```

Повторите сравнение с другим значением, например `2`; после эксперимента
удалите переменную из текущего терминала командой
`Remove-Item Env:STT_BEAM_SIZE`. Значение по умолчанию остаётся равным `1`.

## Предложение исправлений локальной Ollama

После распознавания пользователь может отдельно запросить предложение
исправлений через существующий локальный `OllamaProvider` с моделью `qwen3:4b`.
В запрос Ollama передаётся только текстовая расшифровка и системные инструкции;
аудио, проекты, сотрудники и назначения в этот запрос не попадают. Существующий
provider сохраняет общие `OLLAMA_KEEP_ALIVE` и `OLLAMA_NUM_CTX` настройки.

faster-whisper завершает обработку и освобождает экземпляр модели до того, как
пользователь может вызвать исправление. Ollama запускается отдельным запросом
после нажатия кнопки, а не параллельно с STT. При текущем `keep_alive=0`
Ollama освобождает свою модель после запроса по существующей политике.

Интерфейс показывает оригинальную расшифровку и вариант Ollama отдельно.
Ничего не подставляется автоматически: пользователь сам применяет вариант или
оставляет исходный текст. Если Ollama недоступна, оригинал остаётся в поле и
его можно передать существующему разбору поручения без исправлений. Проверяйте
сроки, числа, имена, требования, навыки, отрицания и условия: локальная модель
может предложить неточную правку, и качество надо проверять на реальных записях.
